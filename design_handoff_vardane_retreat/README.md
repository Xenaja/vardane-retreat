# Handoff: Лендинг женского ретрита «Йога и процветание» (Вардане, Сочи, 9–12 октября 2026)

## Overview
Одностраничный лендинг для продажи мест на 4-дневный женский ретрит по Кундалини йоге.
Задача страницы: передать атмосферу (море, октябрьское солнце, женская мягкость), объяснить программу и снять возражения, довести до заявки (лид-форма + телефон ведущей). Целевая аудитория — женщины 40–60 лет, поэтому крупный кегль, высокий контраст, спокойный тон, никаких «продающих» кричалок.

## About the Design Files
Файлы в этом пакете — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий задуманный вид и поведение, а **не продакшн-код для копирования**. Задача разработчика — **воспроизвести этот дизайн в существующей среде целевого проекта** (React/Next, Vue, обычный статический шаблон и т. п.), опираясь на принятые в кодовой базе паттерны и библиотеки. Если среды ещё нет — выбрать подходящий стек (для такого лендинга достаточно статической генерации: Next.js/Astro/чистый HTML+CSS) и реализовать дизайн там.

Специфика прототипа, которую **не нужно переносить буквально**:
- Все стили заданы инлайново (требование среды прототипирования). В продакшне — обычные CSS/утилиты/CSS-модули, токены из раздела «Design Tokens».
- Появление блоков при скролле реализовано скриптом, который прячет элементы через `element.style.opacity`. В продакшне — CSS-класс + `IntersectionObserver`, обязательно с фолбэком: **контент должен быть видим, если JS не сработал** (это уже ломалось в прототипе).
- Отправка формы — заглушка (валидация + сообщение). Нужен реальный эндпоинт.

## Interactions & Behavior
- **Навигация** — плавный скролл по анкорам (`html{scroll-behavior:smooth}`), учитывать высоту sticky-шапки (`scroll-margin-top`).
- **Появление блоков при скролле**: элементы с маркером reveal стартуют `opacity:0; translateY(18px)`, переход `opacity/transform .9s cubic-bezier(.2,.7,.2,1)`. Показ по `IntersectionObserver` (threshold ~.06, `rootMargin: 0 0 -6% 0`). Обязательно: элементы, уже попавшие в первый экран (`top < innerHeight*1.2`), показываются сразу без анимации; плюс **безусловный таймер-страховка ~1.4 с**, который показывает всё оставшееся (иначе в нестандартных контейнерах прокрутки страница остаётся пустой); при `prefers-reduced-motion: reduce` анимацию не включать вовсе.
- **«Дышащие» окружности**: `@keyframes breathe { 0%,100%{transform:scale(1);opacity:.5} 50%{transform:scale(1.06);opacity:.85} }`, длительности 9–13 с, `pointer-events:none`, `aria-hidden`.
- **Карточки** (программа, результаты): hover — `translateY(-4px)` + тень.
- **Ссылки шапки**: hover — цвет `#A62F55`.
- **FAQ**: нативный `<details>`; «+» → 45° при открытии.
- **Форма**: клиентская валидация — имя и контакт непустые, согласие отмечено; иначе сообщение в строке статуса («Заполните имя и контакт…», «Нужно согласие на обработку данных.»). Успех — «Спасибо. Татьяна свяжется с вами в течение дня.» + сброс полей. В продакшне: POST на бэкенд/CRM, состояния «отправляется / успех / ошибка сети», защита от спама (honeypot или капча), обязательная ссылка на политику рядом с чекбоксом.
- **Адаптив**: без медиазапросов, на `repeat(auto-fit, minmax(...))` — блоки сами складываются в одну колонку. Точки схлопывания заданы значениями `minmax` (330px для двухколоночных секций, 430px для карточек программы). Шапка переносит навигацию на вторую строку (`flex-wrap`). При переносе в продакшн можно заменить на явные медиазапросы, сохранив порядок и отступы.

## State Management
Локального состояния минимум:
- `form.name`, `form.contact`, `form.consent` — контролируемые поля;
- `form.status` — строка сообщения (пусто / ошибка валидации / успех); в продакшне добавить `isSubmitting`, `error`;
- `spotsLeft: number` — конфигурируемый параметр; при `> 0` показывается бейдж «Осталось N мест» в блоке цены (склонение: 1 — «место», 2–4 — «места», иначе «мест»);
- открытость аккордеонов FAQ — нативно в DOM (`<details>`), состояние не нужно.
Загрузки данных нет — контент статический. Единственный сетевой вызов — отправка заявки.
